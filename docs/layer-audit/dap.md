# Layer audit: `dap`  (`+tools/dap`)

**Maturity:** `underbuilt`  
**Upstream delta:** n/a

The layer has real functional bugs that will produce hard errors at runtime: four key bindings point to functions that are not merely deprecated but entirely undefined (no defun), so invoking SPC d I i/r/t or SPC d v will signal void-function. A duplicate 'det' key means SPC d e t silently loses dap-eval-thing-at-point. Two evil-state hooks target modes that do not exist. The README omits one of the two exposed layer variables. The layer has never adopted dap-auto-configure-mode and has no funcs.el or tests. None of these issues have been fixed upstream either. The maturity rating is unchanged: underbuilt.

## Findings

### HIGH · bug · effort S — Duplicate `det` key clobbers dap-eval-thing-at-point

_status: confirmed · deliverable: issue_

The bindings plist has "det" set twice in succession (lines 82-83). spacemacs/set-leader-keys processes these via a while loop calling define-key; the second call for the same key overwrites the first. SPC d e t therefore ends up bound to dap-ui-expressions-add, not dap-eval-thing-at-point. The same overwrite applies when bindings are applied per-mode via apply#'spacemacs/set-leader-keys-for-major-mode. The README table at line 139 is wrong. Fix: remove the second "det" entry; assign dap-ui-expressions-add to a distinct key (e.g. "dea" for 'add expression'), then update the README.

### HIGH · bug · effort S — Four bindings call functions that are entirely undefined, not merely deprecated

_status: adjusted · deliverable: issue_

The auditor described these as 'deprecated no-ops' but this is wrong: make-obsolete in Emacs only sets a symbol property; it does not create a function stub. With no defun, calling any of dap-ui-inspect, dap-ui-inspect-region, or dap-ui-inspect-thing-at-point will signal a hard 'Symbol's function definition is void' error. The auditor also undercounted: not three but four bindings are broken. 'dv' at packages.el:94 also calls dap-ui-inspect-thing-at-point and is documented in README:148. Fix: replace all four broken bindings with dap-ui-expressions-add (which is interactive and pre-fills from region or symbol at point); update the README Inspection section to remove the SPC d I prefix and rename SPC d v accordingly.

### MEDIUM · bug · effort S — Evil-state hooks reference two nonexistent modes

_status: confirmed · deliverable: issue_

The :hook block at packages.el:30-33 has four entries. Two are valid: dap-ui-sessions-mode (define-minor-mode at dap-ui.el:679) and dap-ui-breakpoints-ui-list-mode (generated by bui-define-interface at dap-ui.el:446). The other two — dap-ui-locals-mode and dap-ui-inspect-mode — do not exist anywhere in the installed dap-mode package. The locals panel uses lsp-treemacs-render with no derived mode; the inspect panel was removed. add-hook on a nonexistent hook symbol is silent, so these fail silently. The evil state for the locals buffer is therefore never applied. Fix: remove the two dead hook entries; if evil state for the locals buffer is desired, investigate whether lsp-treemacs-generic-mode or a buffer-local hook can be used instead.
