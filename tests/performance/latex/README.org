#+title: LaTeX display performance benchmarks

This directory contains diagnostic benchmarks for LaTeX fontification and
redisplay.  They are deliberately separate from the ERT suite: elapsed-time
assertions are too sensitive to machine load for CI, while the benchmark
results are still useful when evaluating a change.

* Magic LaTeX batch benchmark

=latex-magic-benchmark.el= times the individual JIT passes supplied by
=magic-latex-buffer=.  With no file arguments it generates a synthetic LaTeX
document.  File arguments allow testing real documents without copying them
into the repository.

The benchmark needs AUCTeX and =magic-latex-buffer=.  Point
=SPACEMACS_BENCH_PACKAGE_DIR= at the package directory belonging to the Emacs
version under test:

#+begin_src shell
SPACEMACS_BENCH_PACKAGE_DIR="$HOME/.emacs.d/elpa/30.2/develop" \
  emacs -Q --batch \
  -l tests/performance/latex/latex-magic-benchmark.el -- \
  "$HOME/path/to/document.tex"
#+end_src

Useful environment variables:

| Variable                         | Default | Meaning                              |
|----------------------------------+---------+--------------------------------------|
| =LATEX_BENCH_ITERATIONS=         | 5       | Traversals of all sampled viewports  |
| =LATEX_BENCH_VIEWPORT_LINES=     | 80      | Lines in each simulated viewport     |
| =LATEX_BENCH_SYNTHETIC_KIB=      | 256     | Generated fixture size               |
| =SPACEMACS_BENCH_PACKAGE_DIR=    | unset   | Package directory initialized first  |

The benchmark samples the start, quartiles, and end of the buffer.  Each
sample fontifies a viewport-sized region and reports median, p95, maximum,
garbage-collection time, and overlays created.  It isolates these scenarios:

- symbol substitution;
- subscript and superscript display;
- the complete prettifier (symbols plus sub/superscripts);
- block highlighting;
- block alignment;
- complete Magic LaTeX passes with each major feature disabled in turn;
- the exact Magic LaTeX defaults configured by the Spacemacs layer, with and
  without its symbol pass;
- the same Spacemacs configuration with the iterative optimized search path;
- all Magic LaTeX JIT passes together;
- AUCTeX font lock alone; and
- AUCTeX font lock with its built-in =prettify-symbols-mode=.

This measures the Lisp work caused by moving into unfontified text.  It does
not measure glyph composition or the GUI redisplay engine; use the GUI scroll
benchmark for that distinction.

* Visual parity tests

=latex-magic-parity-test.el= captures the source ranges, display values, faces,
visibility, priority, and partner overlays produced by Magic LaTeX.  Its
fixture covers static symbols, composed accents, negation, nested scripts,
structural commands, font decoration, block sizing, and alignment.  Candidate
prettifiers can be checked against the installed reference implementation
without relying on subjective screenshots:

#+begin_src shell
SPACEMACS_BENCH_PACKAGE_DIR="$HOME/.emacs.d/elpa/30.2/develop" \
LATEX_BENCH_PARITY_FILES="$HOME/one.tex:$HOME/two.tex" \
  emacs -Q --batch -l ert \
  -l tests/performance/latex/latex-magic-parity-test.el \
  -f ert-run-tests-batch-and-exit
#+end_src

The exported =latex-magic-parity-compare-prettifiers= helper also accepts
arbitrary document contents.  Run it over representative real documents in
addition to the synthetic fixture before accepting an optimization.  Set
=LATEX_BENCH_PARITY_FILES= to a platform-path-separator-delimited list to run
the optimized-versus-reference assertion over real documents automatically.

* CPU profile

=latex-magic-profile.el= runs one batch benchmark scenario under Emacs' CPU
sampling profiler and writes a fully expanded call tree.  This gives function
attribution in addition to wall-clock comparisons:

#+begin_src shell
SPACEMACS_BENCH_PACKAGE_DIR="$HOME/.emacs.d/elpa/30.2/develop" \
LATEX_BENCH_PROFILE_SCENARIO=spacemacs-magic \
  emacs -Q --batch \
  -l tests/performance/latex/latex-magic-profile.el -- \
  "$HOME/path/to/document.tex" /tmp/latex-magic-profile.txt
#+end_src

Set =LATEX_BENCH_PROFILE_ITERATIONS= to control the number of five-viewport
traversals (default 40).  Any scenario listed by the batch benchmark can be
profiled.

* GUI scroll benchmark

=latex-scroll-benchmark.el= measures forced redisplay after jumping among five
viewports.  It records both uncached navigation (fontification invalidated) and
cached navigation.  The scenarios compare ordinary AUCTeX, built-in symbol
prettification, Magic LaTeX without its symbol pass, and the complete Magic
LaTeX configuration with both reference and optimized symbol scanners.

Run this in a disposable GUI Emacs, never the primary Emacs process.  From a
task-specific worktree, the following keeps the init directory and all runtime
state isolated.  The new instance exits after writing the TSV file:

#+begin_src shell
SPACEMACS_BENCH_PACKAGE_DIR="$HOME/.emacs.d/elpa/30.2/develop" \
LATEX_BENCH_ITERATIONS=5 \
  open -W -na Emacs --args \
  --init-directory="$PWD" -Q \
  -l "$PWD/tests/performance/latex/latex-scroll-benchmark.el" -- \
  "$HOME/path/to/document.tex" /tmp/latex-scroll.tsv
#+end_src

* Reference measurements

These are diagnostic baselines, not test thresholds.  They were collected on
2026-09-01 with GNU Emacs 30.2 on an Apple M3 Ultra Mac Studio.  Each row is 50
samples across five viewports.  The source documents remain outside the
repository.

The batch benchmark isolates the JIT/fontification cost.  =spacemacs-magic=
uses the layer's configuration (symbols, su/subscripts, and block highlighting
enabled; block alignment disabled).  Times are milliseconds:

| Document                       | KiB | Scenario                   | Median | p95  | Mean overlays |
|--------------------------------+-----+----------------------------+--------+------+---------------|
| =final-review.tex=             | 222 | =spacemacs-magic=          |  15.09 | 67.93 |          98.0 |
|                                |     | =spacemacs-magic-optimized= |   7.63 | 15.54 |          94.8 |
|                                |     | =spacemacs-magic-no-symbols= |   5.83 |  9.88 |          14.0 |
|                                |     | =auctex-font-lock=          |   2.83 |  4.67 |           0.0 |
|                                |     | =auctex-prettify=           |   3.19 |  5.25 |           0.0 |
| =MKTG6120_Final_Exam_Prep.tex= | 144 | =spacemacs-magic=          |  12.96 | 25.52 |         125.6 |
|                                |     | =spacemacs-magic-optimized= |   5.26 |  6.12 |         125.6 |
|                                |     | =spacemacs-magic-no-symbols= |   6.86 | 11.88 |          16.0 |
|                                |     | =auctex-font-lock=          |   3.32 |  4.09 |           0.0 |
|                                |     | =auctex-prettify=           |   3.61 |  4.42 |           0.0 |
| =midterm-review.tex=           | 120 | =spacemacs-magic=          |  14.39 | 57.82 |         118.2 |
|                                |     | =spacemacs-magic-optimized= |   5.67 | 12.10 |         116.6 |
|                                |     | =spacemacs-magic-no-symbols= |   4.08 |  8.48 |          12.0 |
|                                |     | =auctex-font-lock=          |   3.50 |  4.23 |           0.0 |
|                                |     | =auctex-prettify=           |   3.72 |  4.19 |           0.0 |

The built-in symbol display added only 0.22--0.36 ms to the median ordinary
AUCTeX font-lock cost in these files and created no overlays.  Disabling Magic
LaTeX's symbol pass reduced its p95 by 54--86%.

The optimized search path preserved every canonical overlay property on the
synthetic parity fixture and all three real documents.  It reduced complete
Magic LaTeX median time by 49--61% and p95 by 76--79%.  It combines 242
non-overlapping exact-command rules into 25
order-preserving regexp segments, leaving 155 dynamic or duplicate rules as
individual searches.  The resulting symbol plan has 180 searches instead of
397.  Shared block and script searches now use the same iterative,
non-signaling scan rather than recursive retries and exception-driven failure.
Block traversal is iterative too, avoiding the reference implementation's
evaluation-depth failure and its fallback creation of unrelated offscreen
overlays.  The viewport parity test confirms that every overlay capable of
affecting the visible region remains identical; this explains the slightly
lower mean overlay count in two optimized rows.

The GUI benchmark separately includes forced redisplay.  The p95 for uncached
viewport navigation was:

| Document                       | AUCTeX | AUCTeX + prettify | Magic, no symbols | Magic reference | Magic optimized |
|--------------------------------+--------+-------------------+-------------------+-----------------+-----------------|
| =final-review.tex=             |   2.10 |              1.94 |             21.98 |           32.10 |           26.23 |
| =MKTG6120_Final_Exam_Prep.tex= |   2.00 |              1.97 |             14.92 |           45.33 |           10.51 |

Cached redisplay was much closer (roughly 1.4--2.9 ms), indicating that the
worst pauses arise primarily when newly visible text is fontified rather than
from the glyph renderer alone.  The optimized search path reduced the uncached
Magic p95 by 18% and 77% in these two controlled runs.  Per-viewport document
structure makes pooled GUI tail timings variable, so the exact overlay parity
and batch results are the stronger regression evidence.

In a 200-viewport CPU profile of the optimized =final-review.tex= scenario,
ordinary AUCTeX font lock was the largest named pass at 31% of all samples.
=ml/jit-block-highlighter= fell from 34% before iterative block traversal to
19% afterward, and the optimized prettifier accounted for 18%.  The remaining
cost is now distributed across ordinary font lock, block work, and symbols
rather than dominated by one avoidable scanner path.
