#+TITLE: Performance investigation notes — September 2026

* Scope and stopping rule

Investigation of the =working= fork with Emacs 30.2 and the configured
layers, not an exhaustive audit of every layer or language server.  Keep
features intact; measure actual first-use/editing work rather than treating
nested profile times or synthetic microbenchmarks as end-to-end savings.
No upstream submissions are planned for this session.

* Implemented and installed

Each dependency change is isolated in its fork; Spacemacs pins exact revisions.

| Change | Spacemacs commit | Evidence |

These results come from separate experiments and must not be added together.
No startup improvement is claimed.  Markdown gains concern edits inside
native-fontified fenced code, not arbitrary scrolling.  The valign change
retains width discovery and right-aligned measurements; it adds no cache.

The Org change also avoids an initialization-order problem: eager export
loads org-element, whose LSP API probe creates an Org buffer before the
agenda callback adds org-habit.  The deferred path honors that configured
module; identical loaded-feature sets are therefore not claimed.

* Remaining candidates worth retaining

** Repeated valign passes — measured, requires invalidation analysis

Before combined validation, a real documentation opening produced 285
alignment attempts across 101 positions (not all genuine Org tables).  The width fix reduced pixel-sizing calls from 32,612
to 18,072 but did not reduce pass count.  Plain no-op redisplay caused zero
passes, so this is not evidence of perpetual idle realignment.

Investigate org-indent completion, jit-lock reentrancy, and refontification
separately.  Pixel measurement itself can trigger fontification and nested
alignment.  Do not suppress calls or cache widths without preserving edits,
folds, links, fonts, text scaling, faces, overlays, indentation, and window
geometry.  First-pass widths cannot blindly substitute for right-aligned
render widths because earlier columns already have display overlays.

Final combined tracing classified the 285 attempts as 112 outer calls and
173 nested calls via pixel measurement -> jit-lock -> valign.  The 112 outer
calls comprised 100 real-table positions plus 12 attempts at pipe-prefixed
ASCII directory artwork inside an example block.  Do not describe all 101
positions as real Org tables.

A separate explicitly invoked empty-queue Org-indent callback caused 112
attempts without any completed-buffer hook.  A natural later cleanup of a
dead queued buffer caused 100 attempts during unfolding, also without a live
buffer completion.  Three batch mechanism tests corroborate callback and
fontification-bound behavior.  This identifies a follow-up, not a measured
speedup from a tested second patch.

Potential future fix: use the completed-buffer hook provided by modern Org,
with compatibility coverage, rather than a global post-agent queue-empty
check.  A smaller nonempty-to-empty guard would not resolve all routing/dead
buffer cases.  A blanket reentrancy guard can suppress another table while
jit-lock marks its range fontified, leaving stale alignment.  Defer both
changes until they have multi-buffer, idle-timer, interrupted initialization,
fold/edit/font/scale, and older-Org tests.  No extra production change landed.

** Layout membership — only compelling at large buffer counts

=layers/+spacemacs/spacemacs-layouts/funcs.el= filters all buffers through
linear perspective membership.  Compiled synthetic 5,000-buffer / 2,500-member
case: 17.254 ms original, 0.855 ms existing reverse-index helper, 0.443 ms
per-call hash.  At 300/30: 0.043, 0.048, 0.026 ms respectively; insignificant
practical gain there.  Ten ERT tests passed.

The reverse helper depends on synchronized indexes; deliberately inconsistent
state diverges.  A per-call hash preserves the forward-list authority.  Only
pursue after reproducing sluggish switching/splitting with many buffers.

** evil-mc deferral — shifts work, does not remove it

=layers/+misc/multiple-cursors/packages.el=: initialization 60.441 -> 0.030 ms,
first programming buffer 0.053 -> 60.072 ms in isolated tests.  Combined cost
unchanged; 48 regression checks passed.  Non-autoloaded internal commands
would not appear in M-x until activation.  Existing issue:
[[https://github.com/jlipworth/spacemacs/issues/13][#13 multiple-cursors]].  Not a demonstrated interaction improvement.

** Loaded-feature guard for load hints — inactive in tested configuration

=core/core-spacemacs.el=, =require@LOAD-HINTS=: avoid hint lookup/file probes
when =(featurep feature)= already holds.  Synthetic repeated-require tests
show a large relative improvement, but load hints are disabled in the tested
configuration.  No user startup saving demonstrated.  Test loaded/unloaded,
explicit filename, stale hint, duplicate library precedence, and noerror.

** Discovery and cleanup algorithms — hypotheses, not measured user wins

- =core/core-configuration-layer.el=: repeated directory predicates during
  layer discovery may be redundant.  Preserve nondirectory skips, symlinks,
  category traversal, private overrides, and index ordering.  Warm local APFS
  benefit unestablished; network/Windows filesystems could differ.
- Package orphan classification revisits shared reverse-dependency graphs.
  A per-cleanup memo might help; mock deletion in all tests.  Cycles need
  explicit semantics and cannot be casually changed in destructive cleanup.
- Defun-source cache can be stale when a definition changes within a single
  configuration pass.  Synthetic correctness issue, not a reproduced user
  failure; test function identity/invalidation before optimizing further.
- Existing purpose/ranger/matchit deferrals would benefit from committed
  first-use/load-order regression coverage; do not duplicate those fixes.

** Org default link integrations — possible dependency-level work

=ol-gnus= eagerly loads substantial Gnus code.  Removing it removes link
support and is not an equivalent optimization.  Any lazy refactor needs
Gnus/message link follow/store/search coverage.  Inclusive loader times do
not establish the saving from such a refactor.

* Deprioritized or rejected

- *Modeline diminish*: the tested configuration disables the minor-mode
  segment, so the suspected repeated work does not run.  With it enabled,
  guarded prototype saved only 0.38–0.62 microseconds; 13 tests passed.
- *Frame title*: about 5.36 microseconds/evaluation with the configured GC
  threshold.  Too small to prioritize; caching must preserve dynamic escapes.
- *Dashboard Projectile*: loading its dependency chain is real work, but the
  saved-project lookup itself was only about 0.2 ms in corrected profiling.
  Reading its persistence file directly would duplicate semantics and skip
  cleanup/discovery.  No validated dashboard replacement.
- *Empty dashboard icons*: guard is possible cleanup but other visible icons
  load the same library shortly afterward; negligible likely benefit here.
- *Info+*: apparent excess was a copied-source timestamp bias.  Existing
  integration is already deferred; moving to Info-mode-hook is not equivalent
  because Info+ redefines Info-mode itself.
- *EditorConfig*: eager global setup protects first-file decoding and directory
  local handling.  Ordinary mode/find-file hooks are too late for charset.
- *OPAM discovery*: isolated HOME lacks the real OPAM state, so failure timing
  is not representative.  Deferral also changes precedence for Dune, Merlin,
  UTop and other tools.  Direct argv invocation remains an unmeasured option.
- *Package quickstart/external theme ordering*: inactive in tested settings.
- *GC tuning*: corrected profiles did not make GC the leading bottleneck.
- *LSP/Company delay knobs*: configured completion delay is not computational
  slowness.  Lower delay or disabling diagnostics trades latency against work
  or functionality; do not present as a validated source-code fix.

regression; the remaining ideas are a backlog, not release blockers.
